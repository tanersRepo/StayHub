# StayHub

Booking.com-style marketplace: hosts list properties (hotels, apartments, houses, rooms); guests search by city + dates and book.

## Stack
Next.js 16 (App Router, `src/`), TypeScript, Tailwind v4, shadcn/ui (**radix** style — `asChild` works), Prisma 7 + SQLite via `@prisma/adapter-better-sqlite3` (Postgres in prod), Auth.js v5 (JWT sessions, Credentials + optional Google), zod v4, date-fns, react-leaflet + OSM, Vitest.

## Commands
- `npm run dev` — http://localhost:3000
- `npm run db:migrate` / `npm run db:seed` (wipes and reseeds) / `npm run db:reset` / `npm run db:studio`
- `npm run db:seed:featured` — adds the 10 showcase listings with real photos (`prisma/seed-featured.ts`) to the existing database **without** wiping it; skips ones already there
- `npm run typecheck` (runs `next typegen` first — needed for `PageProps`/`LayoutProps`)
- `npm test` — Vitest unit tests in `src/**/__tests__`
- Seed logins: `host@example.com`, `guest@example.com` — password `password123`

## Conventions
- **Backend = Server Actions** in `src/actions/*.ts` (`"use server"`), validated with zod schemas from `src/lib/validators/`. No REST routes except `api/auth` and `api/uploads`.
- Actions used with `useActionState` return `{ error?: string }`; on success they `redirect()` or `revalidatePath()`.
- **Money is Int minor units (cents)**, but **prices are whole currency units**: nightly rates must be whole (validator `.int()`), `calculatePrice` rounds the discount with `roundToWhole()`, so charged totals never have cents. `formatMoney()` (`src/lib/pricing.ts`) always shows whole units ($599, never $598.50). Converted display prices are rounded to whole units too.
- **Currencies:** `CURRENCIES` (USD, EUR) in `src/lib/currency.ts`. A listing is priced and **charged** in `Property.currency` (host picks it). Guests choose a *display* currency (cookie, set by `setDisplayCurrency()`). Server code gets `getDisplayMoney()` (`src/lib/currency-server.ts`) = display currency + exchange rates, and passes that `DisplayMoney` down; guest-facing browse prices go through `formatPrice(minor, listingCurrency, display)`. Rates are live ECB reference rates from Frankfurter (`api.frankfurter.dev`, no key), fetched with `next: { revalidate: 86400 }` so at most once a day; on failure `getExchangeRates()` returns `FALLBACK_RATES` so pages still render. Conversions are for display only — never charge a converted amount. Records of what was paid (`/bookings/[id]`, `/trips`, host pages) stay in the listing currency. Search price bounds arrive in the display currency and are converted per listing currency in `priceRangeFilter()`.
- **Stay dates are UTC midnight**; a stay is the half-open range `[checkIn, checkOut)`. Use helpers in `src/lib/availability.ts`; never re-implement overlap logic.
- Every `Property` has ≥1 `RoomType` (hotels: several, with `quantity` > 1; apartments: one "Entire place" with quantity 1). Bookings/blocked dates attach to a **room type**. Availability is count-based (`checkAvailability`).
- Booking creation must run inside `db.$transaction` and re-check availability.
- Auth helpers: `currentUser()`, `requireUser()`, `requireHost()` in `src/lib/auth.ts`. Route protection lives in `src/proxy.ts` (Next 16 name for middleware).
- Prisma client is generated to `src/generated/prisma` (gitignored); import via `@/generated/prisma/client`. `postinstall` regenerates it.
- Enum-like columns are Strings (SQLite): Property.type, status, Booking.status, User.role. Keep the allowed values documented in `schema.prisma`.
- Read `node_modules/next/dist/docs/` when unsure about a Next 16 API before guessing.
- **Client components must not import from `src/lib/db.ts`, `storage.ts`, or `properties.ts`** (they pull SQLite/`node:fs` into the browser bundle and the route silently fails to build). Client-safe constants live in `src/lib/labels.ts` and `src/lib/media-limits.ts`.
- Media: `PropertyMedia` holds photos and ≤30 s videos (`kind` IMAGE|VIDEO). `roomTypeId` null = general property media (Media tab), set = photos of one room type (Rooms tab → Photos dialog; photos only, `MAX_IMAGES_PER_ROOM_TYPE`). `order` is unique per property across both scopes; `reorderMedia` reassigns a scope's existing slots. Cover queries use `COVER_IMAGE` from `src/lib/media-query.ts` (general photos first). Uploads go through `POST /api/uploads` (route handler — Server Actions cap bodies at 1 MB); duration is verified server-side by `mp4DurationSeconds()`.
- Pricing: **hosts price rooms date by date on a calendar** (`src/components/host/pricing-calendar.tsx`, in the property editor's Pricing tab and at Host → Calendar & prices; actions in `src/actions/rates.ts`). The room form has no price field. A date's price is its `NightlyRate` row, else the room's optional **default** `RoomType.pricePerNight` (nullable; set in the calendar with `setDefaultPrice`). A date with neither has **no price and can't be booked**: `unpricedNights()` (pricing.ts) / `unpricedAhead()` (rates.ts) find them; the widget treats them as unavailable, `createBooking` refuses them, search skips rooms with any in the stay. "From" prices use `startingPrices()` (lowest default or upcoming dated price; null = unpriced). Publishing requires every room to have a price. A stay costs the sum of its nights. Always price via `calculatePrice(rates, checkIn, checkOut, rules)` where `rates` is a `RateCard` (`{ base, overrides }`, overrides keyed yyyy-mm-dd UTC) built with `rateCardFor()` / `loadOverrides()` from `src/lib/rates.ts` — passing only the base price ignores the host's nightly prices. Dates must be UTC midnight (client picker dates: convert with `Date.UTC(y, m, d)` first). `PricingRule` tiers (minNights → discountPercent) apply to the summed subtotal. Bookings store `subtotalAmount`/`discountAmount` at creation; receipts show those, never a recalculation (older bookings have null and fall back to the base rate). Search prices and filters every room in JS: with dates, by the stay's average nightly price; without, by its "from" price.
- Host pages live under `src/app/(host)/host/`; every page/action loads properties with `getOwnedProperty()` / `assertOwnsProperty()` from `src/lib/host.ts`.
- **Formatting stay dates:** use `formatStay()` from `src/lib/dates.ts`, never `format()` from date-fns directly (UTC-midnight dates shift a day in western timezones). Client date pickers parse `yyyy-mm-dd` as local (`new Date(\`${s}T00:00:00\`)`).
- Search filters: `parseFilters()` (`src/lib/search.ts`) reads city/dates/guests/type/`minPrice`/`maxPrice`/repeated `amenity` off `searchParams` (prices in query are major units, minor units internally) and returns a `query` string that round-trips them; `priceBounds()` sizes the slider. Amenities are a JSON array in a String column, so they are matched with `contains: '"value"'`, AND-ed. UI is `src/components/search-filters.tsx` (sidebar on desktop, sheet on mobile; URL is the source of truth).
- Destination autocomplete: `suggestDestinations()` (`src/actions/destinations.ts`) groups published properties by city/country and ranks them in JS with `rankDestinations()` (`src/lib/destinations.ts`, accent- and case-insensitive). Don't move text matching into a Prisma `contains`: it ignores case on SQLite but not on Postgres (prod), and `mode: "insensitive"` is unsupported on SQLite. UI is `src/components/destination-input.tsx`.
- Support widget: chat bubble in the root layout (`src/components/support-widget.tsx`) → `sendSupportMessage()` (`src/actions/support.ts`) → `sendSupportEmail()` (`src/lib/support.ts`), which emails `SUPPORT_TO_EMAIL` through the Resend HTTP API (`RESEND_API_KEY`; optional `SUPPORT_FROM_EMAIL`) with Reply-To set to the user. Without those env vars it logs the message to the server console in dev and refuses in production. Honeypot field + in-memory per-IP limit (5 per 10 min, single-server only). Messages aren't stored in the DB.
- Guest flow: `searchProperties()` (`src/lib/search.ts`) → `BookingWidget` → `createBooking` (transactional) → `/bookings/[id]` mock pay → `/trips`. Leaflet map is client-only via `next/dynamic` (`search-map.tsx`, `property-location.tsx`). `MapView` always adds an `isolate` class to the Leaflet container — Leaflet's own panes/controls use z-index up to 1000 and never scope themselves, so without it they paint over any dialog/sheet stacked above the map elsewhere on the page.
